Novel OS の改善へのご協力ありがとうございます。貢献は、本プロジェクトのソース公開商用条件とプライバシーの境界を守る必要があります。

## プライバシーと権利の問題はリリースを阻止します

共有する権利を持つ、再利用可能なシステム素材のみを提出してください。次のものは**提出しないでください**。

- 原稿、章の下書き、対話セッション、物語の状態、著者のフィードバック、非公開プロジェクトのテストデータ
- 人物・世界・研究のデータベースや実在人物の記録
- チャットの記憶、ローカルログ、生成されたバックアップ、認証情報、Cookie、端末のパス、非公開エンドポイント
- 著作権のある原文、流出素材、ペイウォール内のコピー、互換ライセンスや帰属表示のない第三者コード

架空で最小限の、明確に合成と分かるテストデータを使ってください。実際の非公開データの名前を変えるだけでは不十分です。

バンドルや物語プロジェクトはソースチェックアウトの外で作成してください。ルートの仮想環境はローカル開発に使えますが、コミットしてはいけません。

## Pull Request を開く前に

```sh
python3 scripts/privacy_scan.py .
python3 -m compileall -q skills scripts
python3 scripts/validate_json.py .
python3 scripts/run_tests.py
```

スキャナーと JSON 検証器は、未追跡ファイルや gitignore 対象を含む作業ツリーのファイルを検査します。Git メタデータ、生成された Python・テストキャッシュ、確認済みのルート仮想環境は除外されますが、追跡済みファイルは検査対象です。シンボリックリンク、読めないファイル、非 UTF-8 ソースは拒否します。ステージ済み差分は別途確認してください。作業ツリーでの合格は、ステージ済みインデックス、Git 履歴、GitHub が保持するオブジェクトをスキャンしたことにはなりません。

次も確認してください。

```sh
git diff --cached --name-only
git diff --cached
```

新たな依存関係、外部ソース、生成物、プラットフォーム固有の動作は Pull Request で説明してください。

## 変更に求めること

- コードと文書の可搬性を保ち、プラットフォームの既定値を上書き可能にする
- 動作変更にはテストを追加・更新する
- 正典・著者の権限と、確認できなければ拒否する安全契約を維持する
- 公開例は合成とし、個人識別情報を含めない
- プライバシー、来歴、検証ゲートを黙って弱めない

## コミットとレビュー

目的を絞ったコミットと命令形の要約を使ってください。Pull Request には管理者のレビューが必要です。セキュリティやプライバシーの修正は、公開 issue でなく非公開の報告を使用してください。

## ライセンス

[LICENSE](LICENSE.md) に基づき配布する権利がある素材のみを貢献してください。改変を明示し、プロジェクト由来の変更には同じライセンスを維持し、必要な第三者の表示をすべて保持してください。これによって著作権が管理者へ移転することはありません。公開 Pull Request に財務報告、支払詳細、私的な創作素材を含めてはいけません。
