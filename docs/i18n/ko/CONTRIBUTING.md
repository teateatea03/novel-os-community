Novel OS 개선에 기여해 주셔서 감사합니다. 모든 기여는 프로젝트의 소스 공개 상업적 조건과 개인정보 보호 경계를 유지해야 합니다.

## 개인정보와 권리 문제는 배포를 막습니다

공유할 권리가 있는 재사용 가능한 시스템 자료만 기여하세요. 다음은 **제출하지 마세요**.

- 원고, 장 초안, 대화형 세션, 이야기 상태, 작가 피드백, 비공개 프로젝트 테스트 자료
- 등장인물·세계·연구 데이터베이스 또는 실존 인물 기록
- 채팅 기억, 로컬 로그, 생성된 백업, 인증 정보, 쿠키, 기기 경로 또는 비공개 엔드포인트
- 저작권이 있는 원문, 유출 자료, 유료 접근 자료 사본, 호환 라이선스 및 출처 표시가 없는 제삼자 코드

허구의 최소한의 명백한 합성 테스트 자료를 사용하세요. 실제 비공개 자료의 이름만 바꾸어서는 안 됩니다.

번들과 이야기 프로젝트는 소스 체크아웃 외부에 만드세요. 루트 가상 환경은 로컬 개발에 허용되지만 커밋해서는 안 됩니다.

## Pull Request를 열기 전에

```sh
python3 scripts/privacy_scan.py .
python3 -m compileall -q skills scripts
python3 scripts/validate_json.py .
python3 scripts/run_tests.py
```

스캐너와 JSON 검증기는 추적되지 않은 파일과 gitignore로 무시된 파일을 포함한 작업 트리 파일을 검사합니다. Git 메타데이터, 생성된 Python·테스트 캐시 및 확인된 루트 가상 환경은 제외하지만 추적되는 파일은 검사 대상입니다. 심볼릭 링크, 읽을 수 없는 파일, UTF-8이 아닌 소스를 거부합니다. 스테이징한 차이도 별도로 검토하세요. 작업 트리 통과는 스테이징 인덱스, Git 기록 또는 GitHub에 보관된 객체를 스캔했다는 뜻이 아닙니다.

다음도 확인하세요.

```sh
git diff --cached --name-only
git diff --cached
```

새 의존성, 외부 출처, 생성된 산출물 또는 플랫폼별 동작을 Pull Request에서 설명하세요.

## 변경 원칙

- 코드와 문서의 이식성을 유지하고 플랫폼 기본값을 재정의할 수 있게 합니다
- 동작 변경에는 테스트를 추가하거나 갱신합니다
- 정본·작가 권한과 확인 불가 시 차단하는 안전 계약을 보존합니다
- 공개 예제는 합성 자료이며 개인 식별 정보가 없어야 합니다
- 개인정보, 출처 추적 또는 검증 게이트를 몰래 약화하지 않습니다

## 커밋 및 검토 방식

각 커밋은 명확한 목적에 집중하고 명령형 요약을 사용하세요. Pull Request는 관리자 검토가 필요합니다. 보안 또는 개인정보 수정은 공개 issue 대신 비공개 신고 경로를 사용하세요.

## 라이선스

[LICENSE](LICENSE.md)에 따라 배포할 권리가 있는 자료만 기여하세요. 수정 사항을 표시하고 프로젝트에서 파생된 변경에는 같은 라이선스를 유지하며 필요한 모든 제삼자 고지를 보존하세요. 이로 인해 저작권이 관리자에게 이전되지는 않습니다. 공개 Pull Request에는 재무 보고서, 지급 상세 또는 사적인 창작 자료를 넣지 마세요.
