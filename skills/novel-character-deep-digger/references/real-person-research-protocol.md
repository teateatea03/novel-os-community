# 真人人物研究、關係與不確定資料保存協定

適用於作家要求「盡量貼近事實」、需要保留公開個人背景、未證實線索或建立關係網時。目標是**不讓可合法查證的關聯、公開背景或流傳說法因過度保守而遺失**，並使每一筆資料的來源、可證性、爭議與使用限制都可追溯；不把線索、外流內容或臆測偽裝成角色正典。

## 1. 來源與資料分級

| 等級 | 可保存範圍 | 最低要求 | 預設呈現 |
|---|---|---|---|
| P1 公開職業／作品 | 公開帳號、工作、作品、活動、組織、公開合作 | 一手或可靠二手來源 | 正文可用 |
| P2 公開個人背景 | 本人已公開或可靠媒體明確報導的姓名、出生年／年齡、教育、公開居住地區、家庭／關係、重大經歷 | URL、短引文、發布與抓取日、來源級別、必要性 | 研究附錄／按需引用 |
| P3 敏感公開主張 | 健康、性別／性傾向、子女、親密關係、受害／法律、財務等已公開事項 | 優先本人明示；否則兩個獨立可靠來源；建立 `claim`，保留異說與時間範圍 | 限創作研究；不可當性格因果捷徑 |
| U 未證實／八卦／外流線索 | 未能獨立證實的八卦、匿名爆料、轉述、搜尋摘要、失效頁面，及使用者或研究中實際查到的外流／doxxing／私密或其他敏感材料 | **可記錄其「存在」**，必有取得／發現日期、來源 URL 或最小識別、內容類型、明確 `UNVERIFIED`／`LEAKED`／`DOXXING` 標籤、風險、不可用限制；不要複製原文、媒體或可識別細節 | 僅限受限研究台帳／claim；不可當事實、不可正文轉述、不可擴散 |
| S 安全隔離 | 密碼、API key、token、銀行／政府憑證、私人聯絡資訊、精確住址、醫療紀錄、性私密素材等高度敏感內容 | 不保存內容或可重建細節；最多記錄「發現 S 類材料，未擷取，已隔離／未使用」與風險理由 | 不得引用或重現 |

「公開」不等於無限制使用。P2／P3 只在能提升關係、時間線、權力／資源條件或作者指定的寫實度時保存；不可為完整而蒐集。U 類的價值是防止研究盲點與關係斷裂：**記錄它是線索，不是認可它是真的**。S 類的價值只保留到「曾發現但未擷取／未使用」這個稽核事實，不保存內容或可回推細節。

## 2. 關係不是附註：先建圖，再寫人物模型

先辨識來源譜系：同一原始貼文、訪談、影片、通稿或匿名說法被多站引用，只算一個 `source_family_id`；每筆主張保存原始來源、轉載／中介鏈、是否取得原文與獨立性判定。不得以轉載篇數製造假交叉驗證。

每一個可能影響角色選擇的公開人物、組織、平台、作品、事件，先列為候選節點。若有證據，保存明確三元組：

`主體 — 關係動詞 — 客體 — 時間範圍 — 證據 — 信心 — 來源類型`

- 可用 `family_of`、`partner_of`、`employed_by`、`founded`、`collaborated_with`、`represented_by`、`member_of`、`appeared_in`、`conflicted_with`、`supported_by` 等具體動詞。
- 關係要有方向、起訖／截至日期與證據；同框、互追、粉絲猜測或單一匿名文章可作 U 類線索／`claim`，但不得升格為親屬、戀情或不和的已證實邊。
- 爭議關係建立 `claim`／事件節點，分別連到各版本來源與 U 類線索；不覆寫成單一事實。
- 對「有人沒被寫入所以失聯」：寧可建立 `person:unknown_role_x` 或 `organization:unknown` 的待查節點，記錄其角色與缺口，也不要杜撰姓名或關係。

## 3. 證據台帳優先與搜尋停止規則

每次研究先讀 `research-operations.md` 與 `research-evidence-run-v2.md`。新 R1／R2 先鎖定 `protocol.json`，再保存 hash-chained events、candidate dispositions、raw／derived artifact provenance、claims／counterevidence 與 checkpoint reviews；交付前執行 `../scripts/validate_research_run.py`。舊 `minis.character-research-manifest.v1` 只能標 legacy provenance，不自動升級。

每次研究先建立主張—證據台帳。每筆至少有：主張、P／U／S 級、來源 URL、原文短引或對 S 類僅記最小描述、來源／抓取日期、直接性、反證／歧義、時間範圍、信心、圖譜節點或關係 ID。

採「廣泛找線索 → 定向取得原文 → 矩陣核驗 → 建模」四段式：保留跨平台、多維度找材料與把細節整合成人物引擎的優點。搜尋摘要、失效 URL、轉載、匿名或八卦資料可以保存為 U 類線索／claim，絕不可直接升格為核心事實。

對每個關鍵主張設定有限查核預算（例如 2 個原始／獨立來源或 3 次定向嘗試）。達到預算仍無可重現原文，就保留 `AMBIGUOUS`／`UNVERIFIED_LEAD` 及查核紀錄，不反覆換關鍵字以製造假確定性。

## 4. 三層交付與小說使用

1. **核查層**：時間線、節點、關係、來源與衝突；P 類資料可作事實使用，U 類僅以明確未證實的 claim／線索呈現。
2. **分析層**：行為模式、替代解釋與信心；不得由 P2/P3/U 資料直接診斷或決定人格。
3. **創作層**：場景反應、人物弧、虛構化方案；清楚標為提案。
4. **受限線索層**：U 類完整台帳與 S 類「已發現未擷取」稽核標記；只供作者在需要更寫實、交叉查核或避免關係遺漏時審閱，絕不可假裝成事實或搬進正文。

真人原型要建立獨立虛構角色，採 `inspired_by` 連結。對 P2/P3，預設只置於「受限研究附錄／圖譜 claim」，在一般摘要與正文引用前先確認它與該場景必要相關；不向無需求的讀者重述。U 類任何使用都須保留 `UNVERIFIED`、來源與衝突標記，並只可作「待查／敘事分支素材」而非真人斷言；S 類不得轉入虛構化素材。

## 5. 交付檢查

- 核心人物與關係是否都能反查到來源？
- 每個重要關係是否有時間、方向、證據與信心？
- 是否保留矛盾版本、U 類線索與查核狀態，而沒有用推論補洞或把未證實主張升格為事實？
- 是否對 S 類只保存發現／隔離稽核、沒有複製內容或可重建細節？
- 是否有「未命名但結構上必要」的待查人／組織節點？
