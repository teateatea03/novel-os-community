# 取得方式隨環境（Session Access Policy）

蒐集資料的重點是**拿到可核對的原文**。登入與否只是環境條件，不是方法禁令。不要為了「保持匿名」或「這條路可能要登入」就把工具拿掉。

## 規則

1. **能蒐集到就用該方法。** 依證據問題選工具：瀏覽器、MCP、crawler、官方頁、RSS、影音、檔案、快照、書目、鄰接來源。方法不因「需要登入」或「不需要登入」預先封殺。
2. **有登入就用登入。** 本機瀏覽器或其他已可用的 session，若已能看見目標內容，就用該狀態取得。
3. **沒登入就用沒登入的方法。** 匿名 HTTP、公開頁、官方 API、Instaloader 匿名 MCP、快照等照常使用。不要停工等登入，也不要為了登入向使用者要帳密。
4. **一條路失敗就換下一條。** 匿名被擋、版面空結果、限流，都改試已登入瀏覽器或其他來源面。失敗標 `blocked`／`UNAVAILABLE`，不視為「事情不存在」。
5. **不索取、不保存憑證。** 不要求密碼、Cookie 字串、Access Token、session 檔。不把帳密／Cookie／Token 寫進研究 run、報告或資料庫（S 類）。用環境裡已經有的登入狀態即可。
6. **不製造身份、不破解門檻。** 不為此註冊新帳、換馬甲、旋轉代理。不把解 CAPTCHA、破解付費牆或攻擊存取控制當成研究步驟。當前身份看不到的內容，換其他方法。
7. **標示取得方式。** 每筆擷取記錄 `access_mode: logged_in | anonymous_public` 與可見範圍。登入後才看得到的內容，不可標成 `public_without_login`。
8. **隱私協定不變。** P1／P2／P3／U／S、source genealogy、不把私人心理當事實等規則，不因登入或方法變多而放寬。

## 路由

```text
目標需要內容
  ├─ 環境已有可用登入且該身份可見 → 用該 session
  ├─ 無登入／該身份不可見 → 免登入公開方法
  └─ 兩條都失敗 → 其他來源面；標 blocked／UNAVAILABLE
```

Instagram、Facebook、X 與一般網頁同一套：匿名 MCP／scraper／公開 API 與已登入瀏覽器都是合法路由，可並用或依環境擇一。
