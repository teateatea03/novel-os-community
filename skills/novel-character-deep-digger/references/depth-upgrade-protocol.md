# 深挖增強協定：由缺口驅動，而非資料堆積（v1.11）

本文件疊加於 Evidence Run v2，不取代原有 schema、媒介 witness、真人研究規範或 validator。適用新 R1／R2，以及使用者要求「繼續挖」「補深度」時。預設本地工具與免費公開來源；不因技能強化而新增付費服務或啟用激進取得層。

## 1. 先重建問題，不要重跑全部搜尋

1. 讀上一輪 protocol、report、claims、reviews、blocked/defer；記錄本輪繼承的 run ID。
2. 選 1–3 個能改變身份、時間線、關係、能力或人物模型的問題。禁止把「更多資料」當作研究目標。
3. 每個問題列：目前答案／不確定點／競爭解釋／能區分它們的原始材料／找到或找不到時如何改變結論。
4. 優先序：身份或版本錯配 → 互相矛盾的 P0 → 原文缺口 → 未處理高價值候選 → 行為樣本盲區 → 其餘背景。這是工作順序，不是事實可信度分數。
5. 使用唯讀工具協助盤點：

```bash
python3 scripts/research_gap_planner.py <run-directory> --output <new-output.json>
```

輸出是待辦建議，不是實際搜尋、事實判定、飽和或完成證明。必須對照原文檢查，不能把建議轉寫成已執行事件。舊資料缺少欄位時顯示 unknown，不假定已完成。輸出檔不得覆蓋既有檔案。

## 2. 身份綁定：先分開，再考慮合併

候選帳號／人物／角色版本另建節點。比較穩定平台 ID、官方明示互鏈、署名作品／credit、公開改名聲明與有效時間；保留支持、衝突與身份來源定位。

- `VERIFIED`：有可核對的明確綁定材料，例如本人／官方明示帳號互鏈或改名聲明，且未見未解身份衝突。它只指身份連結，不保證貼文內容為真。
- `PROBABLE`：有多項相容公開線索，但缺直接綁定或存在時間缺口；只能列候選，不寫入主體的事實卡。
- `UNBOUND`：同名、相似 handle、相同頭像、追蹤／被追蹤、同框或搜尋摘要。各自不足以綁定。
- 身份衝突時保留候選隔離並調查；不要用多數票壓過反證。帳號轉手、改名和角色改編需要時間範圍。
- 不用人臉辨識來跨站識別真人；不推導未公開法律身份、住址、私人聯絡或追蹤行蹤。只研究與任務相關、可適當引用的公開材料。現有登入不等於對第三方私人資料的全面授權。

使用者更正對象時，舊 run 標明不再適用；保留歷史，不把錯誤目標的資料混入新 run。

## 3. 來源譜系與逐項主張

每條主張拆成最小可核對句，將「她說 X」與「X 發生」分開。來源 family 依資訊起源，而非網站數、平台數或 URL 數：同一影片、新聞稿、轉述新聞與跨平台重貼只算同一資訊家族。不同貼文雖可屬不同材料，仍可能出自同一發布者；要另說明發布者集中度，不能假裝獨立外部印證。

遇到關鍵引文，追溯二手文章 → 被引用訪談／影片／公告 → 原句及上下文；找不到原文則保留中介鏈與 `original_retrieved:false`，不得補寫原話。AI 摘要、搜尋 snippet、新聞提問式標題只作導航。

保留來源立場、知情條件、事件距離、是否剪輯／商業腳本／角色演出。短劇角色名、扮演關係和影片情節不得升格為出演者的法律姓名、婚姻或家庭事實。公司頁引用帳號、平台掛載影片、商業合作標籤，不等於股東、法人或雇傭關係。

## 4. 時間與狀態：不要用現在覆蓋過去

分開保存：事件時間、發布時間、更新時間、擷取時間、快照時間，以及主張有效期間。日期精度不足可保存年月、區間或 unknown；不要為排序捏造完整日期。

- 「某報導稱當時 21 歲」保留原句、報導日與來源，不換算為確定出生年／生日。
- 粉絲數、簡介、平台顯示年齡、IP 屬地只是某次擷取時的欄位，不等於出生地、國籍或現居住址。
- 活動邀請、預告、售票頁只能證明計畫；活動完成需場後原文／可核對紀錄。
- Wayback 快照缺頁、JS 空殼、索引未收錄皆不是「從未存在」。

## 5. 讓人物模型真的更深：樣本設計

以公開表達或正典行為為限，建立小型行為證據卡：`場景／時間 → 觸發與可知資訊 → 行為或短引 → 資源與代價 → 替代解釋 → 精確 locator`。

至少比較與問題相關的兩種情境：早期／近期、工作／公開休閒、獨立表達／合作、成功／失敗、低壓／高壓。取不到某種情境就保留缺口，不能宣稱已看見真人私下人格。

先列抽樣框：涵蓋日期、平台／版本、可取樣母體、採樣理由、漏失／刪文／存檔偏差。不要把最近 20 篇或演算法推送當完整人格樣本。平台聲音差異可能實際來自題材、年代或內容類型；比較時盡量控制這些因素。

競爭模型要預先寫不同預測，保留至少一份未參與建模的已取得材料作留出檢查；資料不足時明標無留出，不把重新讀同一素材算驗證。創作場景壓力測試只測敘事模型，不證實真人心理。

## 6. 工具與受阻路由

記錄方法、平台、觀測日期、存取模式、結果狀態、錯誤類型、下次值得重試的條件。歷史「可用／不可用」只代表當時環境；使用時小預算探測，不把過往紀錄當永久結論。

`zero` 是成功查詢但無結果；`blocked` 是限制；`error` 是技術失敗；`partial`／`metadata_only` 描述擷取範圍。後兩者放在 artifact 的 capture_status，不擅改 v2 event result enum。挑戰／CAPTCHA 停該路由，429 依回應降頻；不換帳號、代理或偽造身份繞過控制。不要為湊飽和窗口重複失敗路由。

工具品牌不是硬性單點依賴：IG MCP 或既有 collector 缺檔時記錯誤，轉可用瀏覽器／官方公開頁／原文存檔；不聲稱執行了未安裝工具。

## 7. 增量研究與交付

續挖優先建立新 run，引用舊 run 及 artifact hash；新擷取保存新檔，不覆寫 raw，不重排 event chain、不補造事件。修訂原 protocol 必須保留舊版，且先確認 validator 支援 revision；不支援時改新 run，不能改 hash 讓歷史看似一致。

報告開頭交付四項：**本輪新增／推翻或降級／仍未知／下一個有價值的原始來源**。若無新資料，明說零新增與阻礙，不重複舊履歷冒充成果。

分開報告：結構驗證、來源可得性、主張可信度、研究停止理由、人物模型成熟度。validator PASS 只能說已實作的檢查通過；不能證明內容真實、來源獨立或全網窮盡。高價值未解項可在時間／來源受限下停止，但要保留 `SCOPE_LIMITED`／`RESEARCH_INCOMPLETE` 及使用限制，不偽造完成。

使用者只要求研究時，先交核查層與分析層；不自動寫小說、補私人背景或導入主資料庫。明確要求入庫才走 database-builder 的 snapshot → 增量匯入 → validate。
